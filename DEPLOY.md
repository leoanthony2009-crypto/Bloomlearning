# Deploying Bloom Learning Lab 01 to Netlify (with credential verification)

## What's in the box
- `POUI Learning Lab 01.dc.html` — the course (served at `/`)
- `Certificate.dc.html` — certificate + badge (served at `/certificate`)
- `Verify.dc.html` — public verification page (served at `/verify?id=…`)
- `netlify/functions/issue.js` — POST `/api/issue` → creates a unique ID, stores the record
- `netlify/functions/verify.js` — GET `/api/verify?id=` → public record (no IP, no free-text)
- `netlify/functions/revoke.js` — POST `/api/revoke` (admin key) → marks a record revoked
- `netlify.toml`, `package.json` — routing + the Netlify Blobs dependency
- `support.js`, `badge.svg`, `assets/` — runtime and media

## Deploy (10 minutes)
1. Push this folder to a GitHub repo (Netlify Blobs needs a Git-linked site; drag-and-drop deploys don't install `package.json` dependencies).
2. Netlify → **Add new site → Import from Git** → pick the repo. Build command: leave empty. Publish directory: `.` (already in `netlify.toml`).
3. **Site configuration → Environment variables** → add `ADMIN_KEY` = a long random string (only needed for revoking).
4. Deploy. Your site is live at `https://<name>.netlify.app`.
5. Optional: **Domain management** → add `learn.bloomlearninglab.com` (or similar). Everything — QR codes included — follows the domain automatically because the certificate builds its verify URL from the page's own origin.

## How it works for a learner
- On completion the course POSTs to `/api/issue`; the ID that comes back (e.g. `BLL01-7K3M9Q`) is printed on the certificate, and the QR/verify URL is `https://<your-domain>/verify?id=BLL01-7K3M9Q`.
- If the service can't be reached (offline, or running the file locally) the course falls back to a device-local ID ending in `-L0001`. The certificate then says **"Local record — not registered online"** and the verify page explains it.

## How verification works for an employer
- Scan the QR or open the URL → the verify page shows recipient, course, issue date, issuer, level, skills, status.
- Anyone can also type an ID into the form on `/verify`.

## Revoking a credential
```
curl -X POST https://<your-domain>/api/revoke \
  -H "content-type: application/json" -H "x-admin-key: <ADMIN_KEY>" \
  -d '{"id":"BLL01-7K3M9Q","reason":"issued in error"}'
```

## Viewing / exporting all records
Netlify → your site → **Blobs** → store `credentials` — every record is a JSON file keyed by ID. Download from there when you need a register.

## Honest limits
- Issuance is triggered client-side, so it confirms that a certificate *was issued by your site* to that name on that date — not that the person is who they say. That's normal for a completion certificate.
- The QR image is generated by api.qrserver.com at print time (needs a connection). Swap to a self-hosted QR library later if you want zero external calls.
